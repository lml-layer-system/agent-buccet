# Agent Buccet

Building Ultimate Containment Constraints Every Time.

Agent Buccet is a persistent, CPU-friendly law and scope enforcement layer for AI agents.

It is not a new agent framework.
It is the law layer you add to the agent stack you already run.

It is designed to work wherever agent motion crosses the same real action boundary:
- filesystem
- process execution
- network and recipient sends
- database actions
- system and credential access

That is why the same Agent Buccet Interceptor and Agent Buccet Gravity path can contain:
- Claude CoWork
- Claude Dispatch
- OpenClaw
- NeMo
- OpenAI Agents
- LangGraph
- similar tool-using agent systems

## Install Shell

Hosted-ready install assets are generated by:

```bash
npm run build
```

Then install from the hosted release shell:

```bash
sh dist/releases/install.sh
```

Or, once served from your own host:

```bash
curl -fsSL https://buccet.lml.dev/install | sh
```

Local repo install path remains available:

```bash
sh scripts/install-agent-buccet.sh
```

That installs a thin user-space shell under:
- `~/.buccet`
- `~/.local/bin/buccet`

Then use:

```bash
buccet status
buccet scope add ~/projects/my-app
buccet run -- python my_agent.py
buccet hook build
buccet hook start
buccet hook status
buccet hook run -- python my_agent.py
buccet logs
buccet uninstall
```

If you installed from the local repo shell instead of the hosted installer, initialize first:

```bash
buccet init
```

Current launch boundary:
- hosted-ready install shell is generated now
- public hosting of that shell and release artifacts is distribution work, not runtime work
- deep intercept front-layer assets are in `native/deep-intercept/` and route through the existing intercept server
- even already-open scope still goes through the same runtime decision path; the front-layer never short-circuits authority
- the hook freezes and waits by default; it only fails closed immediately when the hook supervisor marks the brain dead
- many protected processes can freeze and forward into the same Buccet brain at once
- shared pending swarm groups let one lawful approval resolve many matching frozen requests
- additional kernel-level nets can sit in front of the same Buccet brain for high-assurance deployments

## What It Does

Agent Buccet prevents structurally unauthorized actions by default.

It controls:
- law
- scope
- reachability
- approval
- audit

It returns only:
- `ALLOW`
- `DENY`
- `REQUIRE_APPROVAL`

## Core Doctrine

- Agents can propose. They cannot authorize.
- No ambient authority for agents.
- No out-of-scope actions.
- No silent destructive tool use.
- If the path was not issued, the action cannot happen.
- Opened paths become lawful session scope.
- Session law persists until the user ends it.
- Grants can be revoked and expire.
- Untrusted content is proposal, not authority.
- Ledger is law.
- Incomplete ledger traces are non-authoritative.

## Why It Exists

Most damaging agent failures are operational:
- deleting the wrong files
- writing outside the intended workspace
- acting in the wrong environment
- sending to the wrong recipient
- mutating the wrong database
- reading or changing the wrong system/config target
- taking destructive actions from ambiguous remote instructions
- treating prompt content like authority

Agent Buccet exists to stop those failures structurally.

## What It Is Not

It is not:
- a replacement for NeMo / OpenAI Agents / LangGraph
- a prompt-only safety layer
- a conversational guardrail system only
- a separate intelligence framework

It is Agent Buccet:
- containment
- enforcement
- approval
- audit
- defensive meta laws

## Architecture

Bottom:
- Agent Buccet
  - laws
  - scope
  - path orchestration
  - allow / deny / require approval
  - ledger

Middle:
- your agent / action layer
  - interprets request
  - proposes tool/action

Top:
- Telegram / Discord / Slack / CLI / web UI
  - control surface only

The chat interface is not the safety layer.
It is only the entry point.
