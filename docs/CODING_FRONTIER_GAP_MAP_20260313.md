## Bridge Meta-Roots
These are the deeper capability roots still limiting frontier-level coding.

### 1. `META_ROOT_EXECUTION_TRUTH_GAP`
The system still proves more about structural legality than actual execution truth.

What this root causes:
- compile-valid but behavior-weak outputs
- scaffolds that survive smoke checks but not real use
- shallow runtime confidence on apps, games, compilers, and refactors

Law targets:
- generated code must survive family-appropriate execution truth, not only structural witnesses
- runtime truth outranks static admissibility when they conflict
- test truth, import truth, and startup truth must be family-specific and explicit

Implementation layers:
- `lib/lml/coding-execution.ts`
- future real family harnesses:
  - app start
  - API request path
  - parser/compiler pipeline
  - game update/render loop
  - refactor behavior preservation

### 2. `META_ROOT_SEMANTIC_TRUTH_GAP`
The system still collapses more on lawful shape than on precise intended meaning.

- correct family shape with weak behavioral alignment
- weak equivalence checking on refactor and transformation tasks

Law targets:
- semantic intent alignment must outrank family-shape similarity
- behavior-preserving transformations must be checked as behavior, not only shape
- candidate collapse must prefer semantic fidelity over superficial witness satisfaction

Implementation layers:
- `lib/lml/coding-semantics.ts`
- `lib/lml/coding-collapse.ts`
- future semantic equivalence checks:
  - route behavior
  - service behavior
  - parser/compiler stage meaning
  - refactor preservation

### 3. `META_ROOT_PROJECT_SYNTHESIS_BREADTH_GAP`
The system can synthesize lawful project graphs, but not yet with frontier-level breadth and depth.

What this root causes:

- limited lawful alternative constructions
- limited graph search across multi-file structures

Law targets:
- project synthesis must operate over multiple lawful graph families per task
- graph search breadth must remain bounded but materially wider than one canonical pattern
- family emitters must cover alternative lawful decompositions, not one scaffold only

Implementation layers:
- `lib/lml/coding-project-graph.ts`
- `lib/lml/coding-family-emitters.ts`

- `lib/lml/coding-body-fill.ts`

### 5. `META_ROOT_IMPLEMENTATION_SUBSTRATE_POWER_GAP`
The generator is now properly subordinate, but it is still not strong enough at bounded body realization to match frontier coding quality.

What this root causes:
- lawful project graph, weak implementation body

Implementation layers:
